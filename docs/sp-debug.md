# Debug: evidence-driven execution and recovery

Classic `sp-debug` and Advanced `spx-debug` investigate the same defect contract.
The leader owns the session, causal decisions, write authorization, evidence
acceptance and final claim. Native subagents handle bounded independent work;
the workflow does not assume a Python graph engine will dispatch them.

## From entry to closeout

Apply the context-sufficiency preflight first. A sufficient context offers the
existing explicit direct/full choice; invocation is not consent to either
choice or to a new fix. A new full session begins unconfirmed. On resume, use an
explicit slug, validated active binding or one unambiguous matching session,
not the newest filename. Keep still-valid confirmation and accepted framing;
only a material symptom, authority, boundary, risk or UI-baseline change needs
the reason-first checkpoint amendment.

Before repair approval, complete intake and observer framing, then gather safe
bounded evidence. Reuse sufficient map-backed minimum intake. Deep fallback
keeps its wider candidate/family/falsifier coverage, but it is not imposed on a
valid minimum package. The leader schedules Stage 1A causal-map work, checks its
actual output, and only then schedules Stage 1B against that accepted output.
Go artifact operations persist the session; native agent tools execute work.
A source inspection or graph status alone never proves current behavior.

Navigation hints only queue evidence reads; they cannot bypass accepted framing
or authorize writes. Safe bounded diagnosis does not require repair confirmation;
exact evidence-backed repair approval is required before mutation. An absent advisory map uses report-grounded deep intake,
with unknowns and candidate hypotheses explicitly distinguished from facts;
it does not automatically invoke map maintenance. An unavailable artifact
runtime still requires its own recovery. Optional feature artifacts are read
only with a valid binding and do not block standalone Debug.

A confirmed diagnosis-only request ends with the requested findings, evidence
and uncertainty, not an unrequested fix or a fabricated resolved state. Do not
ask the user to verify a nonexistent patch. Missing required diagnosis
evidence remains open; a later repair needs its own authority and fresh gates.

The evidence loop binds the original reproduction, ranked candidate queue,
falsifying observations and owning control loop to current inputs. Test one
causal decision at a time. Independent falsifiers can run concurrently, but
workers must not promote competing root causes or make competing fixes. A
harness/import/permission/timeout failure does not satisfy RED for a different
target defect; when the supporting mechanism is itself the confirmed target,
its matching failure signature is valid evidence. Intermittent failures require
controlled attempts and preserved
outcomes; one successful retry is not proof of resolution.

Check authority, current anchors and the execution guard before any source,
test, harness, configuration or instrumentation write. Renew the guard after
relevant scope expansion or source drift. Guarded supporting recovery has its
own causal and before/after evidence and cannot substitute for the original
target RED. After target causal proof, concrete repair approval and RED, repair the minimum coherent cause. Necessary harness, launcher
or local-tool repairs stay in Debug's authorized recovery scope and return to
the original reproduction. Do not offload ordinary recovery to another workflow
or the user. Diagnosis-only authority still forbids source and instrumentation
writes; recovery does not grant production deployment or other new permissions.

Verify the final integrated revision after removing only owned temporary
instrumentation/resources. Cover the original symptom, regression, owning loop,
related risks and affected consumers; UI failures require the same real-entrypoint
state/viewport/input evidence. Keep failed, skipped, unavailable and stale rows
open. Agent GREEN leads to `awaiting_human_verify`, not `resolved`. Human
confirmation must refer to the currently verified fix. Issue classification or
a resolved child does not close the parent. Preserve the existing cognition,
Learning and execution closeout gates; archive only when requested through the
artifact owner. Do not claim clean completion before all applicable gates pass.

## Parallel work without conflicting evidence

A useful multi-agent split is independent reproduction, owner/boundary tracing,
and contrarian or related-risk evidence, followed by an independent review of
the integrated fix. Select only useful lanes and available tools; small focused
work may remain inline. This is a dispatch plan, not evidence that workers ran.

Each packet names the session/lane, accepted prerequisites, input revision or
relevant digests, exact question, allowed reads/commands, forbidden writes,
expected/falsifying observations, resource budget, result channel and join
criterion. Test commands that touch common ports, databases, browser profiles,
fixtures, caches or external environments are not independent merely because
they read different files. Isolate or serialize them.

At joins, inspect commands, exit codes, evidence bytes/refs, expected/observed
outcomes, input freshness, missing rows and actual side effects. Withhold
acceptance of stale, wrong-session, incomplete or unverifiable submissions.
Valid disconfirming observations remain evidence; never ask a worker to
replace them with the expected answer. Resolve contradictions with a probe,
not a majority vote. A crashed, timed-out or unsafe worker can be cancelled
through its native owner without waiting for a missing result. Preserve
partial evidence and resource ownership, confirm quiescence before redispatch,
and never treat cancellation as acceptance or broadly kill other processes.

Check the live tool surface rather than trusting installation metadata.
After an authorized inline fallback, update the current dispatch fields to
the actual execution path; keep the historical failure as evidence. Required
independent review remains pending without a distinct capable validator who
neither authored nor edits the fix; self-review is not equivalent.

## Resume and state ownership

Use existing `Current Focus`, `Suggested Evidence Lanes`, `Evidence`,
`Candidate Resolutions`, `Execution Intent` and `Resolution`, not a new scheduler
or parallel state file. Save the current probe, accepted/pending lanes, failed
gate, owned paths/resources, evidence basis, recovery attempts and exact next
action at semantic boundaries. Batch same-checkpoint patches when supported.
On a lease conflict reread current state and merge the intended delta without
erasing newer evidence. Inspect a possibly completed action before replaying a
mutation or starting a replacement worker.

Resume the earliest unsatisfied gate rather than repeating the full intake.
Input/source drift invalidates only affected technical evidence and consumers.
A failed closeout receipt does not demand another human confirmation when the
fix and verification are unchanged. Continue independent ready work while a
lane recovers. Only an exhausted safe authorized path or a genuine human gate
justifies an incomplete exit; retain evidence, withheld claims and exact resume.

## Acceptance and regression evidence

Source-contract tests check policy consistency, not model compliance. Installed
integration tests check actual native-format rendering, reference delivery and
missing-file repair without overwriting user edits. Neither proves a model ran
multiple workers, repaired a product, or worked for a requested duration.

The reference-graph unit tests follow explicit read/link edges, not every
installed Markdown file. They detect lost triggers, missing or escaping
paths, nested references and cycles, and ignore examples/comments as read
edges. They check possible reference delivery, not conditional model behavior.
TOML checks use only its embedded prompt, never unrelated sidecar contents.
The real installation tests still require the actual package and must not
be reported passing from the graph tests alone.

```bash
python -m pytest tests/test_debug_execution_loop_contract.py \
  tests/test_autonomous_blocker_recovery_contract.py \
  tests/test_debug_recovery_edges.py
python -m pytest tests/integrations/test_debug_execution_loop_rendering.py \
  tests/test_spx_skill.py tests/integrations/test_base.py \
  tests/integrations/test_unified_specify_runtime_rendering.py \
  tests/integrations/test_advanced_skill_repair.py
```

Real-agent evaluation should bind baseline and candidate commits, runtime and
model/tool versions, profile, scenario inputs, resource budget, actual dispatch
IDs and retained evidence. Compare correctness and original-task completion
before comparing repeated reads, confirmation rounds, tool calls or latency.
Do not invent performance improvements from a shorter prompt or passing text
tests. Use independent reviewers for these scenario groups:

| Scenario group | Evidence required |
| --- | --- |
| New, resumed, ambiguous-session and diagnosis-only intake | Correct selection, intact preflight/confirmation, no unauthorized writes, no repeated valid checkpoint |
| Lightweight and deep intake | Minimum path avoids deep-only obligations; Stage 1B consumes accepted Stage 1A; missing rows are repaired before evidence work |
| Parallel and conflicting probes | Real native dispatch IDs, isolated mutable resources, revision-bound joins, rejection of stale/wrong-session results, no duplicate worker race |
| Target failure and broken harness | Original failing signature, supporting recovery, target RED, final GREEN and resumption of the original gate |
| Intermittent failure and instrumentation | Controlled before/after attempts, observer effects, cleanup and post-cleanup verification |
| Source drift, interruption and lease conflict | Preserved history, invalidated affected consumers, no stale overwrite or duplicate mutation, exact resumed gate |
| Human feedback and closeout failure | Current-fix confirmation, parent retained on classification/child completion, successful receipt before clean claim |
| Unavailable delegation or protected access | Actual recovery attempts, authorized fallback, explicit pending independent review or precise human action without fabricated completion |

The existing package owners already include command references, worker prompts
and Advanced skill references; this change introduces no runtime namespace,
schema or release. Existing projects need normal workflow-asset regeneration
to receive changed files. Missing-file repair alone is not an upgrade of
existing content, and user-modified assets must be preserved.

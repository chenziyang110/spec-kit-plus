# Project Cognition 优化实施与实测

日期：2026-10-11。范围是 spec-kit-plus 源码维护，依据
[原优化方案](2026-10-10-project-cognition-optimization.md)。

原方案的 C0–C7（含 C6a、C6b）均已实施并独立验收；补充完成原生兼容、
安装集成和回放工具验收。最终综合验收及本报告、数据、回放包的精确摘要保存为
同目录的 `2026-10-11-project-cognition-acceptance.json`。
原范围为 10 项、37 行验收，增加 3 项、4 行，共 13 项、41 行；没有缩小分母。

实测结论是：本轮导航任务正确率从 **88/120 提高到 120/120**，
查询运行时和重复导航输出有改善；整体 agent 导航耗时中位数却从
**17.20 秒增加到 19.09 秒**，约增加 11%。这次完成的是全部优化工作包，
尚未证明 agent 整体更快，也未证明 Learning 带来的长期加速。

## 实际 agent 导航前后测

每个阶段为 2 个 profile × 5 类任务 × 4 个条件 × 3 轮，共 120 条。
每阶段启动 3 个独立新 agent，每个连续执行 40 条任务；并非 120 个冷启动会话。
五类任务是定位、解释、排错、构建打包入口、测试入口导航。
任务要求找到 owner、消费者、验证入口及排除错误路线，没有要求实际完成构建或软件交付。

| profile / 条件 | 前测中位秒 | 后测中位秒 | 每阶段样本 |
| --- | ---: | ---: | ---: |
| Classic 首次 | 33.205 | 46.365 | 15 |
| Classic 重复 | 15.590 | 20.232 | 15 |
| Classic 变体 | 18.889 | 21.877 | 15 |
| Classic 源码变化 | 15.797 | 19.842 | 15 |
| Advanced 首次 | 31.724 | 20.031 | 15 |
| Advanced 重复 | 14.551 | 12.106 | 15 |

这些是指定最终记录的任务墙钟中位数，Classic 四条件均退步。
首次确认正确 owner 的整体中位数也从 16.66 秒增加到 18.22 秒。
逐项正确性有 32 条改善、0 条通过转失败；完整角色和源码证据均由非作者验证。

30 条后测重复任务均执行有效 Expand 和单独的 Learning，共 2 次调用，
Compass 调用为零。前测重复任务同样是 2 次调用，已没有新增源码读取字节。
重复任务原生输出中位数：Classic 从 6303 降到 1923 字节，
Advanced 从 6308 降到 1924 字节；不能把输出字节当作模型 token。

整体原生调用却从 257 增到指定记录的 289 次，计入全部尝试为 295 次。
总原生输出为前测 1,113,650 字节、后测全部尝试 2,542,687 字节；
原生耗时总和约 16.95 秒到 66.86 秒。
新源码读取总字节从 31,863,128 到指定记录 30,176,835，
后测全部尝试为 30,264,254；物理源码范围扩大，不能据此声称纯运行时因果收益。

保留原 20 个逻辑角色验收条件。随实现增加 18 个物理路径角色，涉及 8 个事实单元，
独立源码清单从 30 扩到 47 个，正向角色路径事实从 1128 到 1560。
没有删掉原验收条件；变化本身限制了前后测的因果解释。

后测 round 3 两次失败读取的完整恢复墙钟为 57.789 秒、82.523 秒，
指定最终记录只含成功尝试。另一次启动前路径错误只有 0.413433 秒工具耗时，
完整恢复区间不可得，因此全部尝试任务计时只有 119/120，未填零。
round 1 一次修复继续使用原始时钟，与下一条重复任务重叠 37.382 秒；
重复任务绑定保留的旧首次记录，不能把区间相加冒充模型总工作时间。
错误原生参数、源码范围拒绝、启动及编码失败均保留原始记录。

每条配对任务的 Learning 都真实启动，但没有可用索引或匹配记录。
另做的 12 次隔离原生实验验证了既有 Learning 匹配和边界，候选未确认、未提升。
组件变化单独出现时仍可能通过相同 command 匹配；不能声称所有组件变化必然零匹配。
没有从配对任务测得 Learning、Playbook 或 reconciliation 的收益。

## 局部成本与代价

1000 节点、5 次采样的整次 Compass 中位数约 322.4 → 136.6 毫秒，
目录首请求约 311.6 → 116.6 毫秒；SQL 调用从 5087 降到 215。
同时逻辑行从 8325 增到 23684、逻辑值字节从 390876 增到 2049363，
分配约 8.85 → 15.88 MB，目录分配约 6.78 → 9.91 MB，
目录首请求 JSON payload 5909 → 6593 字节。
30 节点目录中位数约 54.6 → 59 毫秒，出现退步。
整次请求仍有两次全图快照，不能宣称 O(page)、物理磁盘 I/O 减少或普遍加速。

C7 的 16 MiB 摘要测试从约 9.65–10.03 降到 7.79–8.25 毫秒，
分配约 16.79 → 1.05 MB。8 × 1 MiB 的准备测试逻辑读取从 16 降到 8 MiB，
分配约 17.30 → 8.73 MB，耗时约 12.21–21.54 → 7.24–8.50 毫秒。
这是请求内复用，不是持久 mtime 缓存；这些读取字节不等于物理磁盘读取。

从 C5 优化前（已经包含 C0 修改）到计入 C4 必需合同后的最终源码入口大小：
Advanced 18942 → 13252 字节，Classic 32854 → 30838 字节，约减少 30% / 6%；
不是早期单独 C5 裁剪比例，也不能推导 token 或任务延迟。

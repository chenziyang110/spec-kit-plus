Trigger: Before presenting a concept and whenever user feedback arrives.
Purpose: Inspect one current direction, repair material craft issues, and turn feedback into immutable follow-up rounds.
Preserved Contract: Present one inspected concept, preserve prior rounds, and freeze only an explicitly approved exact round.

# Critique and iteration loop

Use this reference before presenting a concept and whenever feedback arrives.

## Critique before presentation

Review the concept against the confirmed brief and report only the most
consequential findings. For each finding record:

- `Observed`: the concrete visible or interactive condition.
- `Change`: the exact adjustment worth making.
- `Why`: the user goal, platform convention, accessibility rule, or design
  decision it serves.

Repair blocking craft issues before showing the round. Do not ask the user to
review a known seed, broken layout, or uninspected file.

## Present one current direction

Show the exact round path and summarize its thesis, signature, preserved
decisions, intentional risk, and known trade-offs. Ask what feels right and
what remains wrong. Do not make the user compare three unrelated compositions
in one file.

## Turn feedback into a new immutable round

1. Classify feedback as `preserve`, `change`, `question`, or `out-of-scope`.
2. Resolve one ambiguous feedback item at a time. Keep the current question
   open when the user requests context rather than answering it.
3. Patch the brief's feedback history and affected `DS-*` decisions.
4. Create the next numbered round. Carry forward approved aspects and revise
   the same direction; do not overwrite or silently mutate the previous round.
5. Re-run structural lint, browser inspection, capture, self-critique, and user
   review.

## Freeze only explicit satisfaction

Approval must name the exact inspected round. If wording is ambiguous, ask one
direct confirmation question. After explicit approval, freeze the preview and
handoff sidecars; later changes require another immutable round and renewed
approval.

An audit is different: return a small prioritized set of `Observed / Change /
Why` findings without mutating approved truth. Open a refine successor only
when the user chooses to change that truth.

# Collaborative studio loop

Read for visual `create` and substantive `refine`.

1. Inspect live context and references. State `design_read`, confidence, and the
   few decisions that can still change the outcome.
2. Keep one active question. Ask one high-impact design question at a time,
   include a recommendation or current guess, and do not ask for facts already
   present. Do not advance past an unanswered question; a request for context
   keeps the same question open. Offer 2-3 textual choices only when useful;
   they calibrate the one current concept and are not permission to generate
   three full boards.
3. Stop questioning when subject, audience, job, platform/input, content,
   hierarchy, states, adaptation, accessibility, and boundaries are executable.
4. Probe the live visual capabilities and follow `image-round.md` when image
   generation is available or `html-round.md` otherwise. Use real content,
   commit to one subject-specific visual thesis and signature, and inspect the
   actual image or real browser captures before presentation when inspection is
   available. Otherwise leave visual critique to the user and make no
   visual-quality claim.
5. Present that exact round. Convert feedback into preserve/change/question
   records and revise the same direction in a new immutable round. Never
   overwrite a reviewed round and never branch into three unrelated concepts.
6. After `preview-lint concept`, call `direction-confirm` only after explicit
   user direction confirmation of the named concept. Do not create the sidecar
   automatically from lint or agent confidence. Direction-confirmed is
   non-consumable: it is not approval, not register, and not a Plan/Implement
   input.
7. Freeze only explicit approval of the named inspected round. Ambiguous praise
   is feedback, not approval.

Before each presentation that the session can visually inspect, critique the
most consequential issues as `Observed / Change / Why`, repair known craft
failures, check representative targets, overflow, focus, state coverage,
platform authenticity, and reduced motion, and regenerate/recapture. Runtime
lint proves structural readiness; actual visual inspection plus user review
determines satisfaction.

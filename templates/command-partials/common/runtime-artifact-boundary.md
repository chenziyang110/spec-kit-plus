## Fixed Workflow Artifact Boundary

Canonical workflow artifacts are CLI-owned. Read them with `specify-runtime artifact show --path <project-relative-path> --view summary`, using `--json-pointer`, `--section`, and `--limit` before requesting `--view full`. Mutate each artifact through the specialized owner named by the artifact registry. Generic `specify-runtime artifact prepare` / `specify-runtime artifact submit` is valid only when `prepare` explicitly grants a lease for an agent-editable type; pass the bounded semantic content inline with `specify-runtime artifact submit --content '<payload>'`. Never create a temporary authoring file, directly read or overwrite a canonical artifact, invent an unregistered path, or reuse a lease. `workflow-state.md` is inside this boundary as rich semantic resume/evidence state and is never required-stage authority; CLI-owned `workflow.json` is accessed only through `specify-runtime workflow`. Source code, tests, and other task-scoped implementation files remain normal repository edits.

If one corrected call returns the same `usage-error` or `invalid` summary and blocker, stop value-guessing: do not vary argument values or path syntax again. Inspect `show_argv`, run `specify-runtime api show <capability> --format json`, or use the namespace's supported `--help`, then make one contract-correct retry. An unchanged error after value-only edits means the option may not have been consumed.

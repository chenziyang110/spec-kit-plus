## Document and Asset Placement

Before creating a retained document, report, media asset, or temporary file, use the project-local `specify-runtime assets route` contract to choose its purpose and path under the optional `.asset-policy.json`. Existing canonical artifacts and native source/tool filenames retain their owners; use their specialized runtime or source-edit contract. Temporary output carries task/worker identity and retention. Pass exact output scope to workers and check the final changed paths with `specify-runtime assets check --path <path> --format json` before claiming asset verification; `--path-only` checks placement only. Never move files merely because they were read, enter another workflow, or write routine governance reports. If this runtime lacks `assets.route`/`assets.check`, keep the limitation explicit and use project conventions without claiming those checks passed.

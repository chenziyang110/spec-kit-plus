Project cognition compass, query, and expansion responses carry an `epistemic_contract` with `graph_role=route_candidate_only`, `fact_source_of_truth=live_repository`, `live_verification_required=true`, `graph_only_claims_allowed=false`, and `unverified_claim_action=withhold`. Graph claims are indexed assertions. In `sp-review`, the Leader freezes the Review Universe, dispatches independent read-only Audit subagents, joins every result, sends accepted findings to isolated Fix subagents, and assigns different subagents for revalidation. Approved-scope defects—including missing code, task omissions, large repairs, and unknown root causes—remain owned by Review; only a proven requirement, design, or architecture truth gap may return upstream. Approval requires zero uncovered obligations/surfaces, all packets joined, fresh snapshot-bound evidence, and no blocking finding. Review closeout refreshes the final summary and prepares a fingerprinted `human-acceptance.json` projection of the frozen Human Acceptance Universe, bound to the approved reviewed snapshot and Review-owned runtime targets; Review does not prefill human PASS. `sp-accept` safely starts or checks those immutable targets, records only session readiness/action fields, and performs reversible test-data, start-positioning, and diagnostic preparation while the human performs each new-or-changed requirement journey and supplies structured confirmations plus the final verdict. Accept does not diagnose; every failed observation first goes to the Review Leader, who owns diagnosis, an independent Fix, independent revalidation, and any later proven upstream-truth handoff. Any repair creates a fresh Review cycle and resets every human scenario so no prior PASS survives a changed product.

## Senior Consequence Analysis Gate

Project cognition is necessary but not sufficient for dependency analysis. It gives workflow agents ownership, consumers, state surfaces, change-propagation facts, verification routes, conflicts, and known unknowns. The map points to likely evidence, but the Senior Consequence Analysis Gate turns live project facts into product and implementation obligations.

When work involves lifecycle operations, running or concurrent objects, destructive actions, shared state, downstream consumers, compatibility, security, or multiple plausible behaviors, workflows must preserve:

- Affected Object Map
- State-Behavior Matrix
- Dependency Impact Table
- Recovery And Validation Contract
- Coverage Gaps

For example, "close team" must consider running workers, queued tasks, late result submission, heartbeat state, `status`, `await`, `resume`, `cleanup`, idempotency, and validation evidence before the workflow can claim the feature is ready for the next stage.

Use `CA-###` IDs for consequence obligations that must survive handoff from `discussion` to `specify`, `plan`, `tasks`, `implement`, and `quick`; `analyze` consumes the same obligations only when run as an optional diagnostic or legacy revalidation pass. `fast` upgrades when the gate triggers; `quick` tracks consequences and acceptance locally instead of handing off solely because the task is large or consequence-heavy; `debug` traces the dependency loop and rejects surface-only fixes.

`fast` keeps the bounded direct-delivery skeleton without Quick's durable
workspace or worker lanes: consume-only Learning runs before Project Cognition,
the leader performs all edits directly, targeted verification proves the local
change, and the same leader performs one Lightweight Review. It creates no
worker packet or review subagent and does not claim the independent system
Review contract.
